# PRD: BOM → 零件库 → 装配图 → 零件图(2026-11-15)

> 用户需求(2026-11-15 对话): 出图前先有 BOM; BOM 要认"当前活跃方案"(Plasticity 里多方案并存, 靠显示 / 隐藏切换)、
> 要能把相同零件(实例 + 直接复制)合并计数; BOM 向上接零件库(采购链接 / 供应商 / 价格), 向下接出图;
> 出图顺序 = 先装配图(标清每一个配合)→ 再零件图(由配合拆成单个零件的公差与技术要求)。
> 标注方案由 agent 出, 用户修正补充, 偏好逐次沉淀, 越用越强; agent 不在代码能覆盖的步骤上消耗。
>
> 关联: `PRD-ai-modeling-v2.md`(A6 MCP、A9 映射表、A12 经验库同一机制)、N3d 尺寸记录 / N4 孔特征(`docs/TODO.md`)。

## 0. 总流程

```
活跃方案(可见性 / 视口状态) ─→ ① BOM(识别相同零件, 计数, 层级) ─→ ② 零件库(采购信息, 成本)
                                        │
                                        └─→ ③ 配合(接口识别 + 配合代号) ─→ ④ 装配图(序号, 明细表, 配合标注)
                                                                          └─→ ⑤ 零件图(每种零件一张; 公差 / 技术要求由配合推出)
                                                                                └─→ ⑥ 交付包(PDF 图册 + DXF + BOM 表)
```

贯穿原则(与 N3/N4 一致):
- **代码覆盖确定性步骤**: 范围判定、相同件识别、计数、公差查表(ISO 286)、编译出图、导出。
- **agent 只在需要判断的地方出场**, 且输出的是**对声明式数据的修改**(BOM 条目、配合代号、出图方案), 由代码执行。
- **每一层都有"用户修正 → 事件 → 偏好"回路**, 能写成硬规则的提升为代码规则, agent 的工作量随之下降。
- 所有用户可改的数据都落盘在 `<文档目录>/.pla/` 下(按文档), 跨文档的(零件库、偏好、案例)放 `<exe 目录>/` 或用户目录。

## 1. 活跃方案(BOM 的范围)

Plasticity 里不同方案常放在同一文件里, 用显示 / 隐藏控制哪一套"在用"。

- **默认范围 = 当前可见的实体**: nodes 状态里的 `hidden` / `invisible` / 隔离(`isolations`)集合 + 图层可见性(26.2.3 实测这些都在, 见 shim `nodes.state`)。
- **方案 = 视口状态**: R33 视口状态已能存 / 恢复可见性(稳定 id)。一条视口状态就是一个"方案"; BOM 可以按某个已存的视口状态计算
  (不必先切过去), 也可以对比两个方案的 BOM 差异。
- 用户可在 BOM 面板里手动排除(参考体、辅助几何)/ 包含, 作为该方案的覆盖项保存。
- 草图(Wire)、片体默认不计入; 实体才算零件。

## 2. BOM: 识别相同零件 + 层级

**零件身份**(每个实体):
- 稳定 id: `nodes.node2id`(如 `LD59UK3hcdpoCwun`, 改几何不变)—— BOM 条目、零件库链接、图纸都挂在它上面。
- **几何指纹**(判断"是不是同一种零件", 与位置 / 朝向无关): 体积、表面积、各曲面类型的面数、排序后的边长直方图、
  包围盒三边(排序)、主惯量矩(由显示网格算, 同 A2 的体积算法)→ 带容差比较。
- **实例**: Plasticity 自带的实例 / 资产引用(`node2assetReference` / `assetRoots`)直接视为同一零件。
- **直接复制**: 指纹相同 → 同一零件, 计数合并。
- **镜像件**: 指纹相同但手性相反(左右件)→ 单列, 标"镜像", 默认不合并(采购上是两种件)。
- 名字只作提示(如"杯内六M4x10"), 不作判据; 指纹相同而名字不同 → 合并并提示, 用户可拆开。

**层级**: Plasticity 的组(`ed.groups`: getChildren / getParent, 副本有 14 个)= 部件 / 子装配; BOM 支持树形与扁平两种视图。

**BOM 条目字段**: 序号、零件号、名称、规格、材料(取 Plasticity 材质)、数量、单件质量(体积 × 密度)、来源(自制 / 外购 / 标准件)、
零件库链接、备注; 每条可人工改名 / 合并 / 拆分 / 改数量(覆盖项, 锁定保存)。

**输出**: 面板表格 + 导出 CSV / Excel; 作为 ④ 装配图明细表与序号、⑤ 零件图清单(每种零件一张, 数量来自 BOM)的数据源。

## 3. 零件库(向上)

跨文档的全局库(`<用户数据目录>/parts-library/`, SQLite 或 JSON):
- 零件号、名称、规格、分类、标准件标记、材料;
- 供应商列表: 名称、链接、单价、币种、起订量、交期、记录日期(价格带日期, 便于判断是否过期);
- 可选: STEP / 缩略图(与 N5 常用件库是同一个库)。

BOM 条目 ↔ 零件库: 按零件号 / 名称规格匹配规则 / 几何指纹自动建议链接, 用户确认。有了链接就能出成本汇总(按方案)。
采购动作本身不在范围内(只记录信息)。价格可由用户维护; 若要 agent 帮忙查价, 每次都需用户同意。

## 4. 配合(装配图的核心)

新的记录类型"配合"(在「记录」里与尺寸 / 孔并列), 引用两个(或多个)零件上的面签名:
- **候选识别(代码)**: 不同零件之间的
  - 同轴圆柱(轴线重合、半径相近)→ 轴孔配合候选;
  - 组合孔(N4b 已经知道哪几件叠在一起、过孔 / 底孔)→ 螺栓连接;
  - 贴合平面(相向、共面、投影重叠)→ 定位面 / 安装面。
- **配合代号(agent 提议, 用户确认)**: 如 Ø10 H7/g6、销孔 H7/m6、过孔按 ISO 273; 理由一句话。
  常用选择沉淀为偏好(例: "定位销一律 H7/m6")后由代码直接给。
- **公差数值(代码)**: ISO 286 表查出孔 / 轴各自的上下偏差, 不经 agent。

## 5. 出图方案(agent / 用户 / 编译器共用的数据)

每张图一份 JSON(`.pla/drawings/<doc_key>/<图号>.json`):
- 图纸: 规范配置(制图规范 JSON: 投影法、线型线宽、字体字高、标题栏格式、剖面线、孔标注格式、精度)、图幅、比例、标题栏字段;
- 视图: 主 / 投影 / 剖视 / 局部放大 / 轴测; 朝向与剖切用语义引用(如"主视图 = 最大平面法向""A-A 过 H001 轴线");
- 尺寸: 线性 / 直径 / 半径 / 角度 / 孔标注 / 链式 / 基准式; 引用 = 记录名(D001、H001.R、组名、配合名)或面签名;
- 基准、公差、技术要求;
- 装配图另有: 序号(与 BOM 序号一致)、明细表、配合标注;
- 每一项带 `origin`(rule / agent / user)与 `locked`(用户改过即锁定, 重新出图保留)。

模型改了 → 按签名重新定位后重新编译, 纯代码。

## 6. 出图顺序

1. **装配图**(每个方案一张或按子装配): 视图、外形 / 安装尺寸、每个配合的配合代号、序号、明细表(来自 BOM)。
2. **零件图**(BOM 里每种自制件一张): 自身尺寸(尺寸记录、孔特征)+ 由配合拆出的本件侧公差(如孔 Ø10H7 +0.015/0)
   与技术要求(如配合面粗糙度规则); 标准件 / 外购件不出零件图(明细表里列规格即可)。
3. **交付包**: 装配图 + 零件图(PDF 图册)、DXF、BOM 表、零件库链接与成本汇总。

## 7. 起草与修正回路

| 步骤 | 谁 | 内容 |
|---|---|---|
| 保底方案 | 代码 | 记录 / 孔 / 配合 → 标注; 规则选视图; 套规范与已沉淀的硬规则 |
| 补全方案 | agent | 主视图选择、剖视、功能尺寸与基准、配合代号、技术要求; 输出方案补丁 + 理由 |
| 编译预览 | 代码 | 编译器(见 §9)出图, 面板预览 |
| 用户修正 | 用户 | 面板里直接改条目; 或自然语言("孔距从左边基准标"), 由 agent 转成补丁 |
| 定稿 | 代码 | 导出; 记定稿事件 |

## 8. 偏好与进化(三层, BOM / 配合 / 出图通用)

每次用户修正记一条事件: 改前、改后、零件类别、涉及的特征、用户给的理由。

| 层 | 内容 | 使用者 | agent |
|---|---|---|---|
| 文档层 | 本文档的 BOM 覆盖项、配合、出图方案(含锁定) | 代码 | 无 |
| 偏好层 | 从修正提炼的规则。**硬规则**(代码直接执行: "孔标注 n×M""板件主视图取最大面""BOM 名称格式""销孔 H7/m6")+ **软指导**(给 agent 的上下文) | 代码 / agent | 仅提炼时(批量, 非每次) |
| 案例层 | 定稿的方案 + 模型概要 + 预览图, 按零件类别索引 | 新零件出图时检索相似案例 | 只读 |

进化: 同类修正重复出现或用户说"以后都这样" → agent 提议规则 → 用户确认入库; 硬规则从此由代码执行。
指标: 每张图的用户修正次数、agent token 用量 —— 应随时间下降。

## 9. 出图编译器(底座, 待验证后选定)

- **A. FreeCAD TechDraw**(本机已装): 投影组、剖视 + 剖面线、局部放大、中心线、公差、模板现成; 重, 部分导出可能需带界面进程。
- **B. build123d(几何 / 消隐 / 剖切)+ ezdxf(DXF 标注样式 / 剖面线 / 线型 / 图块)**: 轻, DXF 可编辑; 视图排布、中心线、螺纹画法要自写。
- 先各做一次可行性验证(同一零件: 三视图 + 剖视剖面线 + 孔标注), 比较效果 / 速度 / 开发量后定; 编译器只认 §5 的方案 JSON, 可替换。

## 10. agent 接入

先走 MCP(与 A6 同一套工具): 读模型概要 / BOM / 记录、读写方案与偏好、编译预览、记事件。用户在 Claude 里说"给这个方案出 BOM / 出图";
pla-ui 面板负责预览、直接修正与导出。以后可选在面板里内置"一键出图"直接调用 agent。

## 11. 阶段

- **B1** 活跃范围: 可见性 / 隔离 / 图层 + 按视口状态算; 排除 / 包含覆盖项。
- **B2** 零件身份: 稳定 id + 几何指纹 + 实例 + 镜像判别; 合并计数; 组 → 层级。
- **B3** BOM 面板: 树 / 扁平、改名 / 合并 / 拆分 / 改数量、导出 CSV / Excel; 方案间 BOM 对比。
- **B4** 零件库: 全局库、BOM 链接建议、成本汇总。
- **D0** 编译器验证: FreeCAD vs build123d + ezdxf。
- **D1** 出图方案 + 编译 + 预览 + 面板直接修正 + 文档层保存(不需要 agent)。
- **D2** 配合: 候选识别 + 配合记录 + ISO 286 查表。
- **D3** 装配图: 序号、明细表、配合标注。
- **D4** 零件图: 由配合推出公差 / 技术要求。
- **D5** agent(MCP): 补全方案、配合代号、自然语言修正。
- **D6** 偏好层 + 案例层: 事件、规则提炼、案例检索; 指标统计。

B1–B3 不依赖出图, 单独就有用(先做); D0 可与 B 并行。

## 12. 已核实的事实(副本, 2026-11-15)

- nodes 状态有 `hidden` / `invisible` / `isolations` / `node2id`(稳定 id)/ `node2assetReference` / `assetRoots`; 物体名 = `nodes.getName(item2key(视图))`。
- `ed.groups`: all / getChildren / getParent / getParents / count(副本 14 个组)。
- 副本里的标准件以名字体现(如"杯内六M1.4x10"), 没有用实例 —— 相同件识别必须靠几何指纹, 不能只靠实例。
